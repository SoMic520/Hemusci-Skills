# DOCX修订与终检工作流

## 1. 工具选择

处理DOCX时同时使用本技能与系统的文档处理技能。用户指定LibreOffice时，必须使用指定可执行文件；常见路径为：

```text
C:\Program Files\LibreOffice\program\soffice.exe
```

开始DOCX处理前运行`powershell -ExecutionPolicy Bypass -File scripts/ensure_libreoffice.ps1`。脚本依次检查用户指定路径、系统常见路径、PATH和注册表；未找到时先用WinGet静默安装最新稳定版，WinGet不可用或安装失败时，从The Document Foundation官方网站解析最新稳定版Windows安装包，校验官方SHA-256后静默安装。只有脚本返回已验证的`soffice.exe`路径后才能继续。

不得下载预发布版、第三方重打包程序或来源不明的安装包。安装失败时停止DOCX处理并报告具体错误，不得把普通文本替换或仅修改扩展名冒充LibreOffice处理结果。

不得仅用普通文本替换后改扩展名。必须保留OOXML结构、图片、图表、题注、目录域、页眉页脚、批注和修订。

## 2. 原稿优先

### 2.1 文件链

建立清晰文件链：

1. `原始底稿.docx`：只读，不覆盖。
2. `工作修订稿.docx`：直接由原始底稿复制或解包生成。
3. `LibreOffice终版.docx`：由工作修订稿经指定软件更新域并保存。
4. `渲染PDF/PNG`：只用于版面检查。

若用户否定上一版并要求重做，立即丢弃上一版正文变更，从第1项重新生成。不得在被否定的修订稿上“撤回一部分后继续改”，除非能够证明所有修订均已完全还原且用户同意。

### 2.2 基线记录

修订前记录：

- 文件大小、修改时间和可选哈希。
- 正文有效字符数。
- 段落、表格、图片、图形、批注、修订和域的数量。
- 一、二级标题全文及样式。
- 用户要求保留的特殊编号。
- 外部关系和超链接目标。

最终逐项比较，防止LibreOffice往返保存造成静默丢失。

## 3. 内容映射

逐段修订时，为每个原稿段落建立稳定标识，至少包含段落顺序、原始文本摘要和所在表格或正文位置。新增段落记录其插入锚点和上位标题。不要只按短语搜索定位，因为同一句式可能在多处重复。

修订计划至少区分：

- 原段整体替换。
- 段内短语修改。
- 删除重复段。
- 在指定段后新增正文。
- 恢复隐性标题样式。
- 新增三级或四级标题。
- 修改图题、表题或表内文字。
- 添加批注。

同一段不要同时被两个互不知情的规则重复改写。

## 4. 修订模式

### 4.1 基本原则

- 插入内容使用真实插入修订，删除内容使用真实删除修订。
- 不把彩色字体、下划线或删除线伪装成修订模式。
- 段落属性、标题样式和编号变更也应留下必要的属性修订记录。
- 不接受或拒绝原稿已有修订，除非用户明确要求。
- 修订作者名和时间统一，不冒用原作者身份。

### 4.2 接受修订后的正文

终检必须分别检查“显示所有修订”和“接受全部修订后的逻辑文本”。前者用于查看红线是否清楚，后者用于确认最终报告没有旧句与新句拼接、重复图题、残缺标点和审稿提示。

对于OOXML：接受文本包含普通`w:t`、插入修订`w:ins`和移入修订`w:moveTo`中的可见文字；排除删除修订`w:del`和移出修订`w:moveFrom`中的文字。属性修订`w:pPrChange`、`w:rPrChange`、`w:tblPrChange`等单独统计和检查，不能只以插入、删除数量代表全部修订。

## 5. 批注

### 5.1 应批注的问题

- 专业概念容易误读且本次已作实质改写。
- 标题层级或段落组织发生非机械调整。
- 原文含明显审稿提示、AI套话或不正式表达。
- 表图与正文功能混淆并已重新叙述。
- 用户需要了解为何保留或不改某处。

### 5.2 不应批注的问题

- 已通过普通语病修订解决的轻微问题。
- 对每个标点、空格和同类替换重复解释。
- “建议核实”“还需验证”等无明确证据的笼统提醒。
- 直接否定报告数据，但没有用户授权开展数据审计。

### 5.3 批注锚点

批注应锚定最小但完整的相关文字。锚点不能只落在一个标点上，也不能跨越数页。LibreOffice往返保存后，批注编号可以变化，但批注文本和锚定内容必须保持一致。

## 6. 标题和目录

- 修改标题前先导出标题清单。
- 用户要求不改的一、二级标题按文本、顺序和样式逐项比较。
- 新增下级标题应使用现有同级样式，不手工拼字体模拟。
- 更新目录前先保存工作副本。
- 使用LibreOffice更新所有目录、图表目录和可更新域，再另存最终文件。
- 图题和表题除使用“题注”样式外，还必须采用彼此独立的真实题注标签或自动编号域。图目录只能提取图题，表目录只能提取表题；字段更新后新增、删除、移动题注和正文交叉引用应同步变化。
- 检查目录是否包含修订状态下的删除旧标题；接受修订后的目录应仅保留最终标题。

## 7. 表格和图件保全

保存前后比较：

- 表格数量、行列结构和表内文字。
- 图片、绘图对象、嵌入对象和媒体关系数量。
- 图题、表题和交叉引用。
- 浮动对象锚点、环绕方式和分页位置。
- 外部图片、超链接和其他外部关系。

发现原稿带有隐藏外部超链接或AI平台链接时，先建立“关系文件—关系ID—关系类型—目标地址—所在部件—锚定段落或对象”的对应。若用户要求清除，只删除目标关系及相应文本或对象的链接属性，不删除可见正文，也不误删外部图片、模板或其他不同类型关系。终检确认目标地址及其引用均无残留。

## 8. LibreOffice往返保存

1. 运行`ensure_libreoffice.ps1`取得已验证的可执行文件路径；使用独立用户配置目录启动隐藏实例，避免与用户正在运行的LibreOffice冲突。
2. 打开工作修订稿，更新目录和域。
3. 以DOCX格式另存为新文件，不覆盖原稿。
4. 关闭文档和实例，等待文件写入完成。
5. 重新解包终版，与保存前版本比较正文、表格、标题、批注锚点和外部关系。

若用户确认Word/WPS中的封面实际版式正确，而LibreOffice导出结果单独出现封面拆页或垂直漂移，不得用LibreOffice渲染结果反向修改正确的DOCX封面。应保留用户确认版本及其OOXML参数，把LibreOffice结果作为兼容性现象记录；继续用LibreOffice核对可打开性、对象完整性和封面以外页面。不得为“修好渲染”删除受控空段、缩放Logo或移动落款。

LibreOffice可能重排批注编号或改变域数量；应比较语义内容和锚点，而不只比较内部ID。

## 9. 强制排版处理

凡创建、重排、修订或验收终检DOCX，必须完整执行 [土壤三普专业报告强制排版基准](report-format-requirements.md)。该基准是格式处理的直接依据；不得仅依据肉眼观感、原稿局部样式或软件默认模板整理版面。

排版处理按以下顺序进行：

1. 记录原稿分节、页边距、页码、标题样式、目录域、题注、图片锚点、表格属性和自定义样式，形成格式基线。
2. 设置页顶距1.5厘米、页底距1.75厘米；用分节符区分前置部分和正文，前置部分采用大写罗马数字页码，正文从阿拉伯数字1重新编页。
3. 清除封面的标题级别和大纲级别，统一封面缩进及空行；设置“前言”“目录”及标题1—标题5的真实样式。
4. 按基准统一中文字体、西文字体、字号、颜色、粗体、缩进、行距和段间距。
5. 生成或修复可更新的正文目录、图目录和表目录；把所有图题、表题设置为“题注”样式和独立自动编号域，按实际章号或正式模板校正编号，不硬编码第五章。
6. 处理图表说明段及完整图表块的顺序：说明段在前，其第一条实质性结果句通常在句末引用图号或表号；说明段后空一行，再放图片—图题—图注或表题—表格—表注，最后一条注释后空一行接续正文。说明段与图表块在文档顺序上保持相邻，但不得机械强制较大的图表与说明段整块同页；出现大面积空白时，清理错误分页属性或在同一小节内连同说明段调整位置，使图表仍紧邻主要描述分析段。用户指定保持不动的任意附图均保留内容、尺寸和页面布局。例如附图5.44—5.49只是示例，其他编号按同一规则类推。
7. 将表格调整为版心100%宽度、整体居中、自然行高、重复表头和通用黑色单实线，清除多余空段、底纹及重复叠加边框。
8. 清理未使用样式；保留所有已使用样式、自动目录和对象需要的样式及其依赖链，必要时隐藏未使用内置样式，不得破坏脚注、超链接、修订或特殊对象。
9. 使用指定LibreOffice更新全部目录和字段，另存后重新打开，比较格式基线并逐页渲染检查。

格式修订不得破坏内容修订。若修改样式、分节或目录会影响现有修订记录，必须保留可恢复的工作副本，并在往返保存后复核修订作者、批注锚点、插入删除文本和接受修订后的正文。

## 10. 自动检查

运行本技能脚本：

```powershell
python scripts/scan_report_text.py "终版.docx" --salinization-status unknown
```

必要时指定段落长度：

```powershell
python scripts/scan_report_text.py "终版.docx" --min-body-chars 300 --max-body-chars 1000 --body-start-regex "^第一章" --json
```

当地已确认不存在盐渍化时才把参数改为`--salinization-status absent`，存在时使用`present`。脚本扫描正文、表格、页眉页脚、脚注尾注、批注和文本框中的可提取文字，并按接受修订状态排除删除和移出文字。若自动识别不到正文起止位置，使用`--body-start-regex`和`--body-end-regex`明确边界后才执行总字数判定。

对脚本命中的每一处回到上下文人工判断。专有名称、引用文献题名和合法专业术语可能只是检查线索。脚本能够核对字符级上下标，但不能代替LibreOffice中的继承字体、分页、图像文字和逐页版式检查。

## 11. 全页渲染检查

必须把最终DOCX渲染为PDF和逐页PNG，并检查全部页面。可先看联系表，再对疑似页面原尺寸检查。

逐页检查：

- 字体、字号、行距和缩进是否异常。
- 标题是否落在页尾、正文是否孤行。
- 表格是否越界、跨页表头是否重复、单元格是否遮挡。
- 图件是否裁切、拉伸、模糊或图例不可读。
- 图题和表题是否与对象分离。
- 图表说明段是否位于对象之前，编号是否进入实质性结果句，说明段与图表块、图表块末尾与后续正文是否各有且仅有一个空行。
- 表注或图注是否仍属于对应图表块，空行是否落在最后一条注释之后。
- 页面是否因多余分页符、“段前分页”“与下段同页”、对象锚点或强制整块同页而出现大面积空白，图表是否远离主要描述分析段。
- 页眉页脚、页码和章节分页是否连续。
- 修订标记和批注锚点是否可见且不遮挡正文。
- 是否出现非预期空白页、缺字、乱码或对象丢失。

正文结束后附图另页起排造成的末页留白可以保留，不应为了填满页面移动附图。

## 12. 最终回归清单

- [ ] 最终稿直接来自用户指定原始底稿。
- [ ] 原稿未被覆盖。
- [ ] 一、二级标题及指定编号按要求保留。
- [ ] 实质性三级小节通常3—5段；短方法说明、过渡和小结未为满足段数机械扩写，分析段长度与总篇幅相协调。
- [ ] 接受修订后的总字数满足用户要求。
- [ ] 正文无审稿提示、管理学套话、验证提醒和AI宣传句。
- [ ] 数据、单位、评价范围和表图编号表达一致。
- [ ] 页顶距1.5厘米、页底距1.75厘米，前置与正文页码格式及起始值正确。
- [ ] 封面无标题/大纲级别，“前言”“目录”和标题1—标题5符合强制样式映射。
- [ ] 正文目录、图目录、表目录和页码能够更新，图、表题注标签和自动编号域相互独立，章号来自实际章节或正式模板。
- [ ] 说明段位于图表之前，图表编号嵌入实质性结果句；说明段后和完整图表块末尾（含最后一条注释）后各空一行，未因强制同页造成大面积空白，图表仍紧邻主要描述分析段，用户要求保持不动的任意附图版式未改变。
- [ ] 表格按窗口自动调整、无固定行高，表头加粗、跨页重复，通用框线无重复叠加。
- [ ] 未使用的强调、参考、书籍标题等冗余样式已清理。
- [ ] 批注与修订均为真实DOCX对象。
- [ ] 表格、图件、目录、关系和批注往返保存无异常。
- [ ] 已探测或自动安装最新稳定版LibreOffice，并使用用户指定或安装后验证的可执行文件保存。
- [ ] 已逐页完成视觉检查。
