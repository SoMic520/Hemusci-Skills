# DOCX 语言修复与格式保真

本路径只用于普通润色、术语纠正、翻译和自然化编辑。它不启用模板，不重建文档，也不改变页边距、节、样式、编号、表格、页眉页脚、字段、批注或内联格式。

## 保守执行方式

1. 保留原文件，用 `scripts/docx_language_repair.py extract` 提取 Word 现有 `w:t` 文本节点。每个单元记录原文哈希、所在部件、段落上下文和是否可编辑。
2. 根据提取结果创建 `assets/docx-language-repair-plan-template.json` 的项目副本。每项修改绑定源 DOCX 的 SHA-256、文本单元 ID 和原文字段 SHA-256。
3. 用 `apply` 生成新 DOCX。工具只修改计划中列明的现有文本节点；源文件哈希不符、原文哈希不符、字段或图形所在段落、重复单元、空删除和保护元素变化均默认失败。
4. 用 `validate` 对照源文件、修改稿和计划，核查 OPC 条目、Word 文本节点拓扑、全部非文本 XML 结构、段落及字符格式、字段、图形、表格、编号、节属性和二进制部件。任何计划外文字变化或非文字部件变化均失败。
5. 修改稿仍需运行术语、题材语言、学科语域和逐页渲染检查。格式保真通过不证明译文或科学内容正确。

## 为什么按文本节点修改

Word 会把一个句子拆成多个运行和文本节点，运行可分别承载字体、上下标、域、超链接或修订信息。直接替换整段常会丢失这些属性。该路径宁可要求对多个节点分别规划，也不把“语言润色”变成隐性重排版。

包含域代码、绘图、对象、图片或替代内容的段落默认锁定。确需修改时，应先确定受控编辑范围并使用更精细的人工 Word 修订；不得为了方便解除全局保护。

`--allow-protected-change` 只在用户明确授权数字、单位、引文或标识符变化后使用；即使使用，最终 `validate` 仍会把保护元素差异报告为失败，要求单独的科学变更记录，而不能把它混入普通润色验收。
