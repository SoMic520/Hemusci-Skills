# 中文土壤科学技术标 DOCX/PDF 版式与渲染规范

本文件定义缺少采购人受控模板时的默认技术标版式。它是 Skill 的工程基线，不是国家强制格式。招标文件、采购人模板、电子交易系统限制和装订要求优先。

## 默认格式配置 CPB-1.2

| 项目 | 默认值 |
| --- | --- |
| 纸张 | A4 纵向，210 mm × 297 mm |
| 页边距 | 上 25 mm、下 25 mm、左 28 mm、右 22 mm |
| 页眉/页脚距边界 | 15 mm / 15 mm |
| 正文中文字体 | 宋/明体系；可复现渲染优先经 SHA-256 锁定的 Noto Serif CJK SC，受控模板可指定宋体/SimSun、Songti SC 或 STSong |
| 中文标题字体 | 黑/无衬线体系；可复现渲染优先经 SHA-256 锁定的 Noto Sans CJK SC，受控模板可指定黑体/SimHei 或同类字体 |
| 西文、阿拉伯数字、拉丁学名和变量 | Times New Roman；DOCX 的 `ascii`、`hAnsi` 和 `cs` 字体槽均须设定，PDF 必须实际嵌入或可验证使用 |
| 正文字号 | 五号 |
| 正文段落 | 两端对齐；首行缩进 2 个五号中文字符；1.5 倍行距；段前 0 行，段后 0.5 行；孤行控制 |
| 一级标题 | 黑/无衬线体三号；段前 1.5 行、段后 0.5 行，与下段同页 |
| 二级标题 | 黑/无衬线体四号；段前 1 行、段后 0.5 行，与下段同页 |
| 三级标题 | 黑/无衬线体小四号；段前 1 行、段后 0.5 行，与下段同页 |
| 表格正文 | 宋/明体小五号，Times New Roman 处理西文数字；不首行缩进；单倍行距；段前段后均为 0 行；自动行高，禁止精确固定行高 |
| 表头 | 黑/无衬线体小五号、黑字白底、跨页重复；无受控要求时不加彩色或灰色底纹 |
| 页眉 | 项目名称与“投标文件（技术部分）”，宋/明体六号 |

| 颜色与边框 | 正式技术标默认纯黑字、白底；数据表只保留必要的黑/灰细线；无招标授权不使用底纹、色带、渐变、卡片、装饰性文本框或封面元数据方框 |

## 封面与前置页

封面只放项目名称、文件类别、项目编号、投标人、法定代表人或授权代表、日期等招标要求字段。用居中纯文本段落建立层级，不用表格、浮动形状或文本框包围元数据。未知信息使用统一的 `【待填：…】` 占位符；底稿在交付审查清单中显式标记未配置项，不在正式封面叠加彩色警示框。正式版必须清除全部占位符。

目录使用 Word TOC 域或稳定的静态目录。目录层级与正文 Heading 1–3 一致。目录页码必须在最后一次内容和版式修改后更新；渲染结果中不得出现“错误！未找到引用源”或空目录。

## 段落和标题

使用真实段落样式，不靠空格、制表符或手工加粗模拟标题。`SoilBody` 样式负责正文的五号字、1.5 倍行距、段后 0.5 行、两端对齐和两字符首行缩进；封面、目录、标题、项目符号和表内段落不使用该缩进。字体名称必须同时写入中西文字体槽，并在实际渲染后核验 PDF 字体清单；不得在缺字环境中依赖未知回退字体。标题不得留在页末而正文转到下一页。正文开启孤行控制；表格标题、表格和表下注释尽量保持在相邻页面。

项目符号和编号使用 Word 编号定义。条目跨行时，续行与正文起始位置对齐。技术术语、标准号、单位和代码不因换行被拆开到难以识别的位置。

## 表格

表格只用于可比较的重复字段，例如需求响应、检测项目、进度、成果、风险和审查清单。不得把普通长段落塞入多列表格。

所有表格使用明确的 DXA 宽度；表格总宽度不得超过正文可用宽度。每个单元格具有明确宽度和内边距，不使用固定行高。跨页表格重复表头；长表允许自然分页，不截断文字。短字段居中，说明性文字左对齐；数值按小数位或量纲对齐。

## 页眉、页脚、目录和域

封面与正文使用分节。正文节包含页眉、页脚、页码和目录域。生成器应写入 `PAGE` 与 `TOC` 字段，并设置打开文档时更新域。若 LibreOffice 未刷新目录，使用受控办公软件更新并重新渲染；不得交付空目录。

## 独立生成流程

1. 从 `assets/genre-output-contract-template.json` 建立文体输出合同，先用 `scripts/validate_genre_output_contract.py` 验证篇幅、模板和封面状态。
2. 从 `assets/technical-bid-spec-template.json` 建立项目规格副本。
3. 用 `scripts/prepare_open_fonts.py` 准备经 SHA-256 锁定的中文字体；英文数字使用 Times New Roman。
4. 用 `scripts/build_chinese_technical_bid.js --spec ... --output ...` 生成第一遍 DOCX。
5. 用 `scripts/validate_chinese_technical_bid.py` 检查 OOXML、几何、中西文字体槽、行距、缩进、样式、域、表格、封面、占位符、聊天残留和科学边界。
6. 用 `scripts/audit_chinese_professional_style.py` 审查套话、模糊归因、宣传性形容、机械模板和术语漂移。
7. 用 `scripts/render_artifact.py --font-dir ...` 生成第一遍 PDF 和每页 PNG，并审计 PDF 实际字体。
8. 用 `scripts/derive_toc_page_map.py` 从第一遍 PDF 提取标题页码，回填缓存目录，再生成和渲染第二遍。两遍页码图必须稳定。
9. 按 100% 视图逐页检查：缺字、字体替换、重叠、表格越界、断行、标题孤立、异常空白、页眉页脚、页码、目录、来源链接和占位符。
10. 任何内容或格式修改后重新执行生成—验证—两遍渲染—逐页审查。最终 DOCX、PDF、渲染页数、字体清单、哈希和审查记录必须对应同一版本。

## 自动校验不能证明的事项

OOXML 校验和渲染只能证明文件结构和可见版式满足定义的检查项，不能证明招标响应完整、方法科学正确、资质真实、价格有效或一定中标。逐页视觉复核也不能替代采购需求、学科、法律和最终投标责任人的审批。
