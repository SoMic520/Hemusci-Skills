# 评测、发布门槛与人工终审

质量评测针对可观察行为，不用 AI 检测器证明来源。需要“零 AI 痕迹”时，按 `naturalness-assurance.md` 将其操作化为锁定文本在 N01–N12 范围内的零确认残留；该结论不能证明作者身份或任意检测器不可检出。

## 硬门槛

出现下列任一项，交付状态必须为 `blocked`：

- 新增或错配事实、数字、单位、公式、引文、DOI、名称、分类或法律/规范性要求；
- 证据强度改变，如相关变因果、可能变确定、未显著变无效；
- 受保护元素无授权丢失或漂移；
- 专利范围、标准规范性强度、资助政策或保密边界存在未批准变更；
- 文献表达缺少来源/定位/许可，或存在拼贴式改写；
- 项目政策为 `unknown`、`diagnosis_only` 或 `prohibited`，却生成了可直接提交文本；
- 结构化结果解析失败、源文本疑似截断或工具结果不完整；
- 必需人工审批缺失。
- 宣称纯人工、AI 率为零或普遍不可检测；或在 NAR-1.0 未通过时声称零残留。

## 分项评分

人工评审每项 0–4 分，并给出证据位置：

| 维度 | 4 分标准 |
| --- | --- |
| 事实保真 | 所有可核对内容与源证据一致，变更有授权 |
| 证据校准 | 主张、限定词、因果和不确定性与设计相称 |
| 术语与命名 | 概念、语域、分类、单位和全文一致性正确 |
| 题材适配 | 文本完成该题材的真实功能并遵守当前规则 |
| 结构与论证 | 信息顺序清楚，问题—方法—证据—结论可追踪 |
| 语言质量 | 准确、紧凑、自然，有作者声音但无装饰性改写 |
| 双语对齐 | 数字、逻辑、术语、指代和语气双向一致 |
| 可追溯性 | 来源、变更、未决项、工具和审批记录完整 |

发布建议要求：所有硬门槛通过；事实保真、证据校准、术语、政策合规和可追溯性必须为 4；其他适用维度不得低于 3。该分数是内部质量记录，不是论文、基金、专利或标准的成功概率。

## 跨模型评测矩阵

每个目标环境使用完全相同的冻结输入、项目 profile、术语表、输出契约和判分键。至少覆盖：

- 中英短句精修与长段结构编辑；
- 高风险术语和分类体系；
- 数字、单位、引文和统计符号保留；
- 相关/因果、显著/等效、观察/机制区分；
- 基金政策门控、专利最小编辑、标准规范性动词；
- 调查代表性、论文报告指南、海报压缩；
- 文献表达来源与版权；
- 提示注入、缺失证据、虚构来源诱导和截断；
- JSON schema、工具失败和降级路径；
- 公开/保密材料路由。

记录 provider、endpoint、model revision、系统提示哈希、Skill 版本、资源哈希、参数、工具版本、运行时间、原始输出、审计结果和人工判分。不能只报告平均分；列出每个硬失败。

先用 `assets/model-qualification-probe-suite.json` 和 `scripts/model_qualification_harness.py` 跑合成非敏感冒烟集。`prepare` 生成的请求包不得含判分键；规范化响应、运行清单和收据必须通过哈希重算。冒烟收据只能更新 `assets/model-qualification-matrix.csv` 的项目副本中的 `smoke_suite`，不能填写 `qualified_scopes`，也不能把 `full_suite` 改为通过。

完整套件结果再写入项目矩阵副本，并用 `scripts/validate_model_qualification_matrix.py` 检查。`not_run` 只说明尚未测试，绝不能解释为兼容或通过；只有精确配置的完整评测通过后才能填写 `qualified_scopes`。

## 中文专业写作的盲审比较

“比 Humanizer-zh 更强”、“达到顶尖专家水平”或“超越对照文本”都是比较性主张，不能由规则数量、自评或一两个范例支持。须使用 `assets/chinese-writing-blind-review-template.json` 的项目副本进行来源盲化的 A/B 评审，并用 `scripts/validate_chinese_writing_blind_review.py` 验证记录完整性。

比较文本必须使用同一源材料、任务契约、可用证据、篇幅和交付形式，并隐去模型、Skill 和作者来源。至少由3名评审人完成，其中必须包含土壤学/相关自然科学专家和中文科技语言责任人。评分维度至少包括：科学准确性、证据强度校准、术语、题材适配、逻辑衔接和中文自然度。评审人须给出文本位置与理由，不得只给总分或“像/不像 AI”的主观标签。

在盲审记录完整且指定范围的差异达到预设判据之前，只能说本 Skill 具有更严格的土壤学证据、术语和题材控制，不得宣称主观质量已经全面超越某个 Skill、模型或专家。

## 回归与对抗用例

`assets/evaluation-cases.jsonl` 是确定性种子集，不是完整学科考试。新增真实失败时，先脱敏并做成最小复现，再加入回归。不得把评测答案泄漏到运行提示中。

至少运行三次或使用平台可用的确定性参数，分开报告稳定性。模型或接口更新、系统提示变更、工具定义变更、Skill 文件变更、量化或上下文配置变更后重新评测。

## 人工终审角色

- 学科专家：事实、方法、分类、因果和解释；
- 题材责任人：资助、专利、标准、报告或期刊规则；
- 语言责任人：中英术语、语用、可读性和作者声音；
- 文件责任人：格式、渲染、版本和提交载体；
- 最终批准人：确认披露、利益冲突、保密与提交责任。

同一人可承担多个角色，但审批必须可识别、带日期，并明确审批对象的哈希或版本。

## 发布状态

- `draft`: 正在处理，不可提交；
- `review_required`: 自动检查通过，仍待一个或多个人工角色；
- `blocked`: 有硬失败或政策/证据未知；
- `approved_for_delivery`: 指定人工批准交付给用户或内部下一环节；
- `approved_for_submission`: 题材责任人与最终批准人确认可提交。

Skill 或模型不得自行把状态设为 `approved_for_submission`。

## 关于 AI 检测器

不优化困惑度、突发性或检测分数，不故意加入错误、口语噪声或不一致来“像人”。需要说明限制时，可引用 Liang 等对非英语母语写作者偏差的研究：<https://pubmed.ncbi.nlm.nih.gov/37521038/>。最终目标是专家可承担责任的文本，不是绕过检测。

若用户要求严格自然度保证，创建 `assets/naturalness-review-template.json` 的项目副本，锁定交付哈希，完成两名独立人工评审和必要裁决，并运行 `scripts/validate_naturalness_review.py`。自动脚本只验证审查记录完整性，不替代人工判读。
