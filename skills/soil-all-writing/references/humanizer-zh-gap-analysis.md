# Humanizer-zh 原技能审计与取舍

审计对象：本机 `humanizer-zh/SKILL.md`，审计日期 2026-08-16。本文件记录新 Skill 为什么不能直接在原技能上叠加土壤词表。

## 可保留的能力

- 能识别宣传性语言、空泛重要性、模糊归因、聊天残留、通用乐观结尾和同义词轮换。
- 提醒编辑者关注信息具体性、句法经济、段落节奏和读者负担。
- 反对把所有文本写成相同的三段式、排比和模板段落。
- 明确提到保持核心含义和预期语调。

这些只适合作为最终语言层的诊断线索，不能成为科学文本的首要编辑规则。

## 主要缺陷

### 中文包落后于英文包

同机英文 `humanizer` v2.9.1 已补充“不得虚构”、授权样本优先、技术/法律文本不强注入个性，以及不要把单个表面特征当作 AI 证据。这些修正应吸收。英文包仍保留“去除 AI 写作模式”的总目标，并一方面硬性禁止所有长破折号，另一方面又承认单个破折号不是可靠证据，规则内部不一致；它同样缺少土壤学术语、题材、证据和政策门控。因此新 Skill 不直接串接任一 Humanizer 包。

### 目标定义错误

原技能以“去除 AI 痕迹”“像真人”为中心，并以 45–50 分宣称“已去除 AI 痕迹”。这种目标不可可靠验证，也容易滑向检测器规避。新 Skill 将目标改为事实保真、证据校准、术语、题材功能、作者责任和可追溯性。

### 可能诱导内容虚构

原技能的完整示例把空泛的软件描述改成“批处理、键盘快捷键、离线模式”和具体测试反馈，但输入并未提供这些事实。科学编辑不能用“具体化”补造结果、功能或来源。新 Skill 对缺失信息只列待核问题或占位符。

### “注入灵魂”不适合高风险科学文本

原技能建议增加观点、感受、幽默、第一人称、跑题和“允许一些混乱”。这可能适用于个人随笔，却会损害方法、专利权利要求、标准条款、调查报告和基金材料的责任边界。新 Skill 只从作者授权样本建立可观察的风格表，不制造个性。

### 规则机械且会误伤专业表达

“两项优于三项”“打断连续同长度句”“段落结尾必须变化”“出现此外/然而就考虑删除”“听起来像金句就重写”等规则按表面信号判断。科学文本中的三类机制、固定报告结构、规范性重复和逻辑连接可能是必要信息。新 Skill 判断每个结构的功能，不按词频或句长强制变形。

### 中英混杂且中文本地化不足

原技能直接移植英语 `-ing`、标题大小写、弯引号等特征，有些在中文中不适用；同时缺少中文科技写作的主语省略、结构式摘要、术语首现、数字单位、全半角和规范性动词。新 Skill 使用中文高质量期刊和官方材料建立独立语料层。

### 缺少学科与题材路由

原技能对论文、基金、专利、标准、调查报告和海报使用同一套自然化思路，没有说明何时重复必须保留、何时第一人称可用、何时规范性强度不可改变。新 Skill 为每类主要载体单独路由。

### 缺少学科语域防污染

原技能主要识别泛化的 AI 写作特征，但不能判断“口径、闭环、赋能、抓手、对齐、颗粒度”等管理咨询或互联网表达是否属于土壤学语域，也无法区分“沉淀经验”与化学“沉淀反应”、“能力矩阵”与统计矩阵、“构建生态”与土壤生态系统。新 Skill 增加 `domain-register-and-word-control.md`、可审计词表和确定性扫描；先按词义确定科学对象，再替换含糊表达，并保护合法技术词义。

### 没有科学受保护元素

原技能只说“保持含义”，未系统保护数字、单位、公式、统计符号、分类、化学式、样品 ID、引文、图表引用、因果强度和不确定性。新 Skill 在改写前后运行候选元素提取和差异检查。

### 没有术语、翻译与分类控制

原技能没有概念级 termbase、权威来源、分类版本、双语回查或高风险术语决策。对土壤分类、SOC/SOM、stock/sequestration、available/extractable 等概念不足以安全处理。

### 没有证据与文献来源治理

原技能未要求主张—来源绑定、全文定位、DOI 核验、许可记录或避免拼贴式改写。新 Skill 只保留短且可追溯的表达片段，优先抽象修辞骨架。

### 没有政策、保密和人工责任

原技能未设置资助机构 AI 政策、审稿保密、专利披露、标准起草、版权、外部模型传输和人工终审门控。新 Skill 对高风险任务采用 fail-closed 清单。

### 评分不可复现

原技能的“真实性”“节奏”“信任度”1–10 分依赖主观印象，并把总分直接映射为 AI 痕迹清除程度。新 Skill 使用硬失败、分项证据、盲审和跨模型冻结用例；不输出 AI 百分比。

### 缺少工程化验证

原技能没有工作副本、文件差异、结构化清单、确定性脚本、版本/哈希、回归集或平台能力探测。新 Skill 将这些纳入 managed-project 模式。

## 新 Skill 的取舍表

| 原策略 | 新 Skill 处理 |
| --- | --- |
| 删除宣传、空泛归因和聊天残留 | 保留，作为末级语言诊断 |
| 强制打散三项、句长和段落模式 | 删除；按科学功能判断 |
| 注入观点、幽默、感受和混乱 | 删除；只匹配授权作者样本 |
| 用具体内容替代空话 | 改为只使用已验证内容，缺失即标记 |
| 通过“真人感”评分验收 | 删除；改为事实、证据、术语、题材和追踪门槛 |
| 通用语言表覆盖所有文本 | 删除；先学科和题材路由，再做语言层 |
| 只清理表面 AI 词，不判断学科语域 | 升级为学科语域审计；默认拒绝管理咨询和互联网词，按词义给出科学替换，并保留合法技术词义 |
| 去除 AI 痕迹 | 改为不优化检测器；仅按 NAR-1.0 对锁定文本声明“定义范围内确认残留数为零”，同时遵守披露和人工责任 |

## 可执行融合验收

“吸收”不能只写在提示词里。当前融合按以下证据验收：

| Humanizer 类能力 | `soil-all-writing` 中的落点 | 验证方式 |
| --- | --- | --- |
| 聊天残留和模型自述 | N01 与确定性失败模式 | `audit_chinese_professional_style.py` 回归失败用例 |
| 宣传腔和无证据拔高 | N02、N04、题材语言配置 | 硬失败模式与需人工判读的诊断模式分开，避免误杀科学意义陈述 |
| 模糊归因 | N03、主张—来源映射 | “研究表明”等无定位归因作为失败用例 |
| 强制三项、镜像排比和固定段落壳 | N05、N06 | NAR-1.0 按修辞功能人工判定，不按三项或句长机械删改 |
| 同义词轮换 | N07、项目术语库 | 术语一致性和保护元素复核，不为了“变化”替换科学对象 |
| 为具体而虚构 | N08、科学诚信规则 | 缺失信息只能标记，保护元素差异测试拒绝新增或改变事实 |
| 因果和机制拔高 | N09、证据强度规则 | 相关性、非显著、外推边界冻结用例 |
| 文体错配 | N10、29 个题材配置 | 题材和段落级语言配置验证 |
| 科研图表结果与分析语体 | N09、N10、用户任务契约、图像预检、图型证据边界、字数计数与专用审计 | 拒绝主观视觉评价、冗余统计引导语、空泛条件限定、图像像素冒充原始统计量、符号阈值猜测、含量—储量/固存越界、参考线阈值化、协变量过度解释和无证据机制断言；用户要求优先控制图表号位置、空项处理、分析深度和连接语；不把“结果表明”“总体而言”“值得注意的是”机械列为禁词；24类确定性失败和44个冻结正反案例 |
| 抽象名词、套话和跨行业黑话 | N11、学科语域词表 | 120 项逐项拒绝/警告测试，并测试 74 个合法技术语境；其中 30 项来源化候选保持人工复核待完成，正式释放时所有语域警告均为待处置阻断项 |
| 作者声音 | N12、授权作者风格表 | 只从作者本人或获授权样本校准，不模仿名家或制造“人味” |
| “零 AI 痕迹”宣称 | NAR-1.0 | 锁定哈希、双人独立评审、必要裁决和声明边界验证 |

词表例外也属于验收范围：只有与文件哈希、段落哈希、出现序号和字符位置同时绑定的受控来源记录可以放行；同段重复词不得被一条例外整段放行。全局白名单、哈希不一致、出现序号或位置错误、非人类审批和未命中的例外均失败。

## 结论

原技能可作为普通中文文案的表层清理清单，但不能安全承担土壤学或自然科学专业润色。新 Skill 已把其有效诊断作为末级语言检查吸收，而不是把原 Skill 作为运行依赖；同时重建了科学诚信、中文语料、专家来源、题材与段落级语言校准、学科语域、术语、翻译、版权、模型适配和验证体系。
