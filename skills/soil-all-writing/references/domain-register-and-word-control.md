# 土壤学科语域与用词管控

本文件用于阻止管理咨询、互联网运营、泛公文和生成式套话混入土壤学及相关自然科学文本。它与术语库分工如下：术语库决定一个科学概念应当叫什么，本文件决定某个词即使语法正确，是否属于当前学科、题材和语篇单元。

## 基本原则

1. 专业化不是把普通词替换成抽象名词，而是写清对象、变量、条件、动作、证据和责任主体。
2. 先判断词义和功能，不做粗暴的子串封禁。“生态系统”“矩阵效应”“沉淀反应”“两端对齐”均可为合法术语或排版指令，不能因包含常见字词而删除。
3. 对无明确科学含义的管理或互联网词实行默认拒绝。只有当它是受控来源中的原文、法定名称、采购条款、专门技术术语或不可改动引文时，才可保留并记录原因。
4. 不用同义词掩盖含糊。“闭环”和“全链条”不与“口径”等一般含糊词并列定性：前两者首先按翻译干扰处理，必须回到源文，确定它实际指反馈控制、措施验证、样品流转、具体过程或起止阶段，再重建中文命题。它们同时受目标语专业语域约束，在撰写者自有中文和中译文中不设技术语境豁免；只有不得改写的引文、正式题名或采购条款才能按准确出现位置建立例外记录。源文—译文规则见 `translation-and-alignment.md`。
5. 正文、表题、图题、摘要和结论均受管控；引用、受控条款和参考文献题名只标记，不擅自改写。

## 默认拒绝的外来语域

在正式土壤学、农业资源环境和相邻自然科学文本中，下列用法默认不得进入干净稿：

- 管理咨询式：口径、闭环、抓手、赋能、打通、拉通、底层逻辑、组合拳、赛道、痛点、卡点、颗粒度、反哺、质量门、责任接口；
- 互联网运营式：落地、沉淀经验、沉淀能力、知识沉淀、成果沉淀、成果输出、价值输出、端到端、问题关闭；
- 空泛行政式：建立健全长效机制、形成工作合力、全方位推进、多措并举、持续发力；
- 项目和商业隐喻：全链路、复盘、打法、触达、撬动、盘活、护城河、卡位、破局、全栈、一站式、数字底座、数据中台；
- 宣传和竞争套话：打造、助力、颠覆性、降维打击、标杆、前瞻布局、抢占制高点、从零到一；
- 责任和外推套话：兜底、加码、压实责任、高位推动、协同发力、由点及面、可复制可推广；
- 政策、项目和产品套话：战略布局、精准发力、攻坚克难、提质增效、跑通流程、画像、创新引擎、成果转化加速器、迭代升级、数智化；
- 媒体和趋势套话：释放动能、破圈、出圈、硬核、深耕行业、创新生态圈、洞察、引领、久久为功；
- 含义未展开的泛词：场景、链路、实现路径、发展路径、方法论、维度、体系化、系统性、精准化。

证据已收集、待独立土壤学人工复核的候选层还包括：顶层设计、统筹谋划、落细落实、走深走实、工作格局、治理格局、一盘棋、共建共治共享、问题导向、需求牵引、筑牢根基、横向协同、纵向贯通、数据要素价值、数据资产治理、全域感知、全程管控、全流程监管、过程留痕、公式化“三清单”、“一张图”管理、新范式、多部门联动、精准施策、同频共振、非技术含义的深度融合、泛称科技支撑，以及标准化/规范化/数字化标签堆叠。这 20 项在词表中保持 `warning` 和 `evidence_gathered_human_domain_review_pending`；普通审计提示人工处置，严格释放模式直接阻断。未完成人工复核前不得把它们改成已正式晋级的永久 `error` 控制。

后四项并非在所有上下文中都违法。例如，生命周期评价、土壤—植物系统、迁移路径、通信链路、矩阵、生态、沉淀均可能是严格术语。只有明确写出技术对象、定义、方法或受控来源时才保留；不得用它们替代实际内容。

## 高风险词的按义替换

| 不专业或含糊用法 | 先确定它实际所指 | 优先改为 |
| --- | --- | --- |
| 数据口径 | 数据来自哪里、包括什么、如何统计 | 数据范围、统计单位、纳入规则和计算方法 |
| 评价口径 | 用什么指标、阈值和规则判定 | 评价依据、指标定义、分级阈值和判定规则 |
| 监测口径 | 对象、点位、频次和方法是否一致 | 监测对象、布点方法、监测频次和检测方法 |
| 统一口径 | 哪些定义或方法需要保持一致 | 统一指标定义和计算方法；按同一检测方法处理 |
| 管理闭环 | 哪些动作构成反馈与验证 | 发现问题、采取纠正措施并验证措施有效性 |
| 质量闭环 | 是样品追踪、复核还是偏差处置 | 样品流转可追溯；结果复核；偏差调查与纠正措施验证 |
| 研究闭环 | 是否只是说研究结构完整 | 目的、方法、结果和结论完整对应 |
| 技术闭环 | 是控制系统还是任务流程 | 写明输入、处理、输出、复核和异常处置步骤 |
| 全链条 | 是样品流转、数据处理还是物质过程 | 从采样、运输、制备、检测到归档的各阶段；或列明投入、迁移、转化和归趋 |
| 赋能 | 实际产生何种能力或效果 | 提供数据支持、提高测定精度、缩短处理时间、降低不确定性 |
| 抓手 | 具体措施或工具是什么 | 关键措施、实施工具、控制环节、监测指标 |
| 对齐 | 哪两个定义、版本或结果需要一致 | 核对；保持一致；建立对应关系；按同一版本执行 |
| 颗粒度 | 是空间分辨率、分类层级还是数据单元 | 空间分辨率、时间分辨率、分类层级、最小评价单元 |
| 链路 | 是数据传输、样品流转还是证据关系 | 数据传输过程、样品流转记录、证据对应关系 |
| 场景 | 是试验条件、使用范围还是情景假设 | 试验条件、应用条件、适用范围、模拟情景 |
| 实现路径 | 是步骤、机制、传输方向还是技术方案 | 实施步骤、作用途径、迁移路径、技术方案 |
| 底层逻辑 | 是理论依据还是因果解释 | 理论依据、判断依据、作用机制；无证据时写“可能解释” |
| 沉淀经验 | 形成了什么可核查材料 | 总结操作要点、形成记录、修订规程、建立经验证的方法 |
| 成果输出 | 具体交付什么 | 提交数据集、图件、技术报告、论文或专利申请文件 |
| 全生命周期 | 是否真正实施生命周期评价 | 生命周期阶段；从采样到归档；仅在按标准开展 LCA 时使用“生命周期评价” |
| 质量门 | 是阶段检查、转序条件还是停止条件 | 阶段质量控制、进入下一阶段的条件、质量控制点 |
| 责任接口 | 是人员、机构还是职责分工 | 责任主体、责任人、职责分工 |
| 问题关闭 | 是已纠正、已复核还是决定不处理 | 问题已纠正并复核、处理状态、处理完成日期 |
| 复盘/打法 | 是复核记录、回顾性分析，还是研究方法、技术方案 | 复核原始记录；开展回顾性分析；研究方法；实施步骤 |
| 全链路/数字底座 | 是样品流转、数据处理，还是数据库和计算设施 | 从采样到归档；数据获取、处理、复核与保存；数据库；数据管理平台 |
| 打造/助力 | 实际动作是什么，影响了哪个可测对象 | 建立、建设、制备、编制；为具体判断提供依据；提高或降低具体指标 |
| 可复制可推广/由点及面 | 是否有外部验证、抽样依据和明确适用条件 | 报告验证范围、抽样设计、适用条件和外推边界 |
| 提质增效/降本增效 | 哪个质量指标、成本项或效率指标发生变化 | 写明指标名称、比较基准、变化量和测定或核算方法 |
| 跑通流程/迭代升级 | 哪个流程经过何种验证，哪个版本修改了什么 | 完成流程验证；更新至具体版本；报告修改项和验证结果 |
| 土壤画像/区域画像 | 用哪些变量、尺度和分类方法表征对象 | 土壤性质表征；指标空间分布；列明变量、尺度和分类方法 |
| 引擎/加速器/催化剂 | 是真实设备、化学物质，还是宣传性因果隐喻 | 驱动因素；促进因素；具体物理设备或化学催化剂名称；说明证据 |
| 聚焦/洞察 | 是具体聚焦技术，还是研究对象和证据结论 | 共聚焦显微镜等技术名保留；其余改为“研究、分析、结果表明、提供依据” |
| 高质量发展/新质生产力 | 是否为必须引用的受控政策术语 | 有来源时作为政策原文准确引用；科研正文改为可测目标、变量或评价指标 |

替换后仍须复核事实。不得为了消除含糊词而补造流程、效果或责任主体。

## 合法专业词不得误伤

以下词只有在其技术含义成立时保留：

- **生态**：土壤生态过程、生态系统服务、生态化学计量等；“构建产业生态”不属于土壤学表达。
- **矩阵**：试验设计矩阵、协方差矩阵、样品基质及基质效应；“能力矩阵”须改写为具体人员能力或职责要求。
- **沉淀**：沉淀反应、沉淀物、选择性沉淀等化学含义；知识或经验“沉淀”不保留。
- **路径/途径**：污染物迁移路径、代谢途径等有对象的科学含义；空泛的“发展路径”“实现路径”不保留。
- **机制**：只有研究设计和证据支持作用过程时使用；一般相关性结果不得因润色变成“揭示机制”。
- **系统/体系**：土壤—植物系统、分类系统、经明确定义的评价指标体系可保留；“系统性提升”“体系化赋能”不保留。
- **模型输出**：在统计模型、过程模型或软件接口中可用；项目交付物不得笼统写为“成果输出”。
- **两端对齐、左对齐、右对齐**：属于排版术语，不受正文用词禁令影响。
- **聚焦**：共聚焦显微镜、聚焦离子束、激光聚焦和声场聚焦属于技术表达；“聚焦赛道”“聚焦需求”不作为科学论证。
- **深耕**：深耕处理、深耕措施和深耕深度属于耕作技术表达；“深耕行业/领域”属于商业隐喻。
- **催化剂、加速器、引擎**：化学催化剂、粒子加速器和明确的软件计算引擎可保留；把组织、政策或成果称为“催化剂/加速器/引擎”时应改写为可验证作用。
- **端到端、全生命周期、一体化和深度融合**：端到端语义分割、按标准实施的全生命周期评价、水肥药一体化和多源数据深度融合可以保留；脱离模型、方法、技术组成或验证条件的同形词仍须展开。

- 官方摘要检索也发现“实践闭环/全链条”见于[宅基地复垦研究综述](http://pedologica.issas.ac.cn/trxb/article/abstract/trxb202504020154)，“顶层设计”见于[土壤污染防治技术体系讨论](http://pedologica.issas.ac.cn/trxb/article/abstract/trxb201710250488)，“新范式”见于[植物—土壤反馈综述](http://pedologica.issas.ac.cn/trxb/article/abstract/trxb202506290314)。期刊发表只能证明真实用例存在，不能证明其适合无条件迁移到论文、基金、标准或技术报告。每个候选的来源与边界记录在 `assets/domain-register-learning-ledger.csv`；题名、作者、日期、DOI、官方页面、用途和禁止拼贴边界另见 `assets/domain-register-source-registry.csv`。

## 题材差异

- **论文、学位论文、综述**：默认采用最严格的学科语域。所有外来管理词均须展开为变量、条件、过程或证据关系。
- **基金申请**：可使用“研究内容、技术路线、关键科学问题”等规范表达，但不得使用“痛点、抓手、赋能、闭环”等词制造力度。
- **技术标、研究报告**：采购文件或委托书中的原词可在逐条响应处原样引用；撰写方自己的解释和方案仍应改成具体技术语言。
- **标准、专利、SOP**：受控术语和法律范围优先。来源原词不得擅改，但必须在术语记录中注明依据；非受控套话一律删除。
- **公众材料**：可以用普通词解释专业概念，但不使用营销热词代替事实和风险边界。
- **排版、软件、遥感与机器学习说明**：保留确有定义的界面、通信、模型或版式术语，不把软件行业用法扩散到科学结论。

## 审计与例外

使用 `scripts/audit_chinese_professional_style.py` 时自动加载 `assets/domain-register-lexicon.json`。命中硬性项即失败，并给出按义替换方向。正式释放前使用 `--fail-on-register-warnings`，使“聚焦、洞察、系统性提升”等依赖语境的项目在未处置前同样阻断发布；该参数不把所有一般性自然度提示机械升级为错误。受控来源要求保留时，先用 `--write-exception-candidates` 生成精确出现位置清单，再复制 `assets/domain-register-exception-template.json` 建立项目例外记录，并通过 `--exception-record` 传入。例外记录必须绑定被审文件 SHA-256、段落 SHA-256、原词、段落号、该词在本段的第几次出现、字符起止位置、来源类型与快照哈希、来源定位、保留原因、责任审校者、审批角色和带时区时间。例外只放行这一次准确出现：同段再出现同词、相邻段落或修改后的段落都不自动放行。文件或段落哈希不一致、出现序号或字符位置错误、例外未实际命中、责任人不是可追溯人类审校者或字段不完整时，审计失败。

机器匹配不能理解全部词义。审校者还须检查：

- 词语是否属于对应学科的常见、可定义表达；
- 是否能在高质量同题材文献、标准或官方技术文件中找到同义用法；
- 该词是否明确指向可观察对象、变量、方法、关系或责任；
- 删除该词后是否暴露出原句没有实质信息。

## 持续学习和更新

本 Skill 不从模型生成文本自动“学习”，以免把错误循环写回规则。新词进入管控表必须走以下流程：

1. 记录原句、题材、段落功能、拟表达的科学含义和风险；
2. 在同学科、同题材的高质量中文期刊、官方标准或专家署名材料中检索真实用法；
3. 分类为“默认拒绝”“特定词义可用”“规范/来源锁定”或“合法专业词”；
4. 为每个默认拒绝项给出按词义替换，而不是单一同义词；
5. 复制 `assets/domain-register-learning-ledger-template.csv` 建立候选台账；当前证据层见 `assets/domain-register-learning-ledger.csv`。任务失败实例和两项优选来源齐全时，状态只能到 `evidence_gathered`；
6. 使用 `scripts/validate_domain_register_learning_ledger.py ... --lexicon ... --source-registry ...` 验证证据、候选词表、官方来源注册表和回归编号的双向绑定，为每一项增加拒绝和合法用法测试；
7. 证据已收集但待人工复核的项目只能以 `warning` 进入词表；严格释放模式必须处置该警告，不能因“候选”而忽略；
8. 只有可识别的独立土壤学科审校者签名并注明日期后，状态才可改为 `domain_reviewed` 或 `promoted`，并决定是否升级为 `error`。Agent、Codex 或 AI 标签不能充当人工审校者；
9. 更新 `assets/domain-register-lexicon.json` 后运行结构、正反例、来源台账和完整回归测试，再升级词表版本。

这个流程允许词表不断扩展，同时防止模型把一次改写、单篇材料或频率低但正确的专业词自动写回正式规则。所谓“学习”是受控的证据更新，不是从生成文本无监督吸收。
